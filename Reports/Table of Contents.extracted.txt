  For 1.1 Background and Motivation
  - Urban bike demand is highly time/weather dependent (hourly, seasonal, holiday, precipitation,
    temperature effects are explicitly modeled).
  - Project motivation is operational prediction + decision support through web API/dashboard, not just
    offline modeling.
  - You can position it as a move from static/manual planning to data-driven short-term demand
    estimation.
    Inference: this “manual planning pain” is inferred from the system design and feature set, not
    explicitly written as business text in code.
  For 1.2 Problem Statement
  - Core technical problem: predict hourly bike rental demand from multimodal inputs (time + weather +
    context).
  - Practical problem: avoid under/over-allocation by producing reliable demand estimates and exposing
    them via deployable endpoints.
  - ML risks explicitly addressed in code: data leakage prevention, time-aware validation, artifact/
    runtime consistency checks.
  For 1.3 Research Objectives
  - Build a leakage-safe prediction pipeline for hourly bike demand.
  - Compare multiple regressors (RF, GB, XGBoost, LightGBM, Stacking).
  - Select best model using objective metrics (R²/RMSE/MAE + CV behavior).
  - Deploy prediction and analytics interfaces (API + web UI).
  - Preserve reproducibility with artifact manifest/config and tests.
  For 1.4 Scope of the Project
  - Included:
      - Seoul bike dataset (data/raw/seoul_bike.csv)
      - Supervised regression for demand prediction
      - Feature engineering + model comparison
      - Flask app + dashboard + export/history
      - Dockerized deployment path
  - Excluded:
      - Live IoT ingestion/realtime streaming sensors
      - Causal policy optimization
      - Multi-city transfer learning
      - Production MLOps stack (online retraining orchestration)
  For 1.5 Project Contributions
  - Unified training pipeline replacing fragmented legacy scripts.
  - Explicit leakage controls (time split, lag handling, train-only scaling).
  - Strong predictive result with stacking ensemble.
  - End-to-end system: model artifacts + API + analytics + history + export.
  - Artifact contract and runtime validation for safer deployment.
